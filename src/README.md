# Xin Skill Vault — source

Wails v3.1 + Go 1.26 + Vue 3 / TypeScript desktop app.

## Run

```powershell
wails3 dev
```

`wails3 dev` builds the frontend, generates bindings, starts Vite and launches the native window.

## Test

```powershell
go test ./internal/...
```

Covered: SKILL.md frontmatter, slug, hashing, import/copy, Junction creation and removal, broken/drifted detection, importables, link-source tracing, recursive folder discovery, schema migrations, content labels, groups/tags/notes, manual sources, project targets, directory management, vault relocation, close-action settings, and network import parsing / safe extraction.

## Build

```powershell
wails3 build
# -> bin/XinSkillVault.exe
```

## Frontend preview

```powershell
cd frontend
npm install
npm run dev
```

Without a Wails host the frontend uses `src/lib/mock.ts`. The mock mirrors the real `Snapshot` shape and supports every interaction. In Wails, `src/lib/api.ts` calls the Go service.

## Notes

- The local index lives in the OS config directory, not inside the skill vault.
- `frontend/bindings` is generated by `wails3 generate bindings`; do not edit by hand.
- Skins are token-only; components must not hard-code colors.
- Typography uses `--ui-font-family` and `--font-scale`; all font sizes use `calc(px * var(--font-scale))`. Default scale is 1.12 for high-DPI readability.
- Skill content is labeled factually as `executable` / `script` / `none`; there is no risk score or import blocking.
- The system tray uses `app.SystemTray`; the close hook honors `window.closeAction` (ask/quit/tray).
- The vault path is stored as `vault.path`; moving it migrates skills and rebuilds link distributions.
- Window sizing compensates for Wails v3.1 high-DPI bounds on Windows.
